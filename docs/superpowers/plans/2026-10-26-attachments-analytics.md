# Вложения и аналитика

Цель: прикреплять и скачивать файлы указаний и задач, анализировать исполнение в стиле Work Board.

Архитектура: существующие Electron main → IPC → renderer service → Pinia/компонент. Без новых зависимостей. SQLite получает последовательную миграцию; файлы хранятся в `<имя базы>.files/{instructions|tasks}/{id}/`, пути в БД относительные.

- [x] Вложения: проверить копирование, одинаковые имена, отмену, ошибки, сохранность при неудачной записи, скачивание и смену базы. Выбор файлов даёт временные токены; копирование и изменения выполняются при сохранении карточки, отмена формы не меняет данные. Удаление владельца каскадно удаляет метаданные и его файлы.
- [x] Аналитика: параметризованные агрегаты SQLite, период по сроку исполнения, тип записи, статус, важность задач, исполнитель указания. Показатели и графики текущего состояния, распределение сроков по месяцам, пустые состояния. У задач два состояния: активная и выполнена; у указаний три существующих статуса. История смены статусов не восстанавливается из updated_at.
- [x] Интерфейс: AttachmentPanel (список и действия, v-model изменений), useAttachmentDraft (выбор/скачивание), AnalyticsWorkspace (композиция), AnalyticsFilters (фильтры), AnalyticsCharts (графики), analyticsStore (запросы и защита поколений). Сохранить CSS-токены, скругления, светлую/тёмную темы и адаптивность.
- [x] Проверка: unit/integration tests, сборка, реальный Electron smoke с вложениями и аналитикой; обновить README и архитектуру.

Риски: подмена пути, смена базы во время диалога, потеря файлов при ошибке SQLite, одинаковые имена, неверное толкование графика как истории. Для каждого добавить проверку либо явную подпись в интерфейсе.

Проверено: npm run check — 143 теста, сборка успешна; npm run test:desktop — полный сценарий Electron пройден.
