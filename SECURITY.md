# Безопасность

Для сообщения об уязвимости используйте **Security → Report a vulnerability**
в [репозитории Work Board](https://github.com/greedval-us/work-board/security/advisories/new),
если закрытая отправка включена. Если кнопка недоступна, запросите у владельца
закрытый канал связи через issue без описания уязвимости.

В закрытом сообщении укажите версию приложения, среду, минимальный сценарий,
влияние и способ воспроизведения на искусственных данных.
Не отправляйте рабочие базы, персональные данные, ключи или неочищенные журналы в публичные issue.

Основные границы проверки: доверие к источнику IPC, безопасные публичные ошибки,
доступ renderer к файлам и Node.js, выбор и миграции SQLite, изоляция поколений базы
и содержимое Excel. Исправления готовятся для актуального состояния репозитория;
отдельный график поддержки старых версий пока не установлен.

## Зависимости и оценка предупреждений

Проверяйте обе группы зависимостей:

```sh
npm audit --json
npm audit --omit=dev --json
```

Повторный аудит 23 октября 2026 года после обновлений дал следующий результат:

| Проверка | Moderate | High | Critical | Всего |
| --- | ---: | ---: | ---: | ---: |
| Все зависимости | 4 | 11 | 0 | 15 |
| `--omit=dev` | 2 | 0 | 0 | 2 |

До обновлений полный аудит сообщал о 23 зависимостях, включая одну critical.
Числа отражают пакеты и связанные транзитивные предупреждения, а не количество
независимых способов атаки. Обе команды завершаются с ненулевым кодом из-за
оставшихся предупреждений; итог не является «чистым» аудитом.

Electron указан в `devDependencies`, но его runtime входит в готовое приложение.
Аудит с `--omit=dev` не заменяет проверку Electron и инструментов сборки.
Отсутствие вызова уязвимого API в текущем коде — оценка достижимости,
а не доказательство безопасности всего пакета.

В этой ревизии установлены точечные обновления Vue `3.5.44`, PostCSS `8.5.31`,
Vite `7.3.7` и Electron `38.8.6`. Обновление Electron остаётся в прежнем major
и закрывает только часть предупреждений этой ветки. В частности, исправление
[подмены ответов `executeJavaScript` через service worker](https://github.com/electron/electron/security/advisories/GHSA-xj5x-m3f3-5x3h)
выпущено в `38.8.6`; приложение не регистрирует service workers.

Чтобы сохранить electron-builder `24.13.3`, используются ограниченные overrides:

- `app-builder-lib → tar: 7.5.21`. Critical
  [ошибка ограничения распаковки](https://github.com/isaacs/node-tar/security/advisories/GHSA-23hp-3jrh-7fpw)
  исправлена в `7.5.19`, а последующее
  [переполнение стека при выборе файлов](https://github.com/isaacs/node-tar/security/advisories/GHSA-r292-9mhp-454m)
  — в `7.5.21`. Новая версия сохраняет CommonJS-вход и используемый сборщиком
  `create(options, files)`. Это обновление транзитивного major; при изменении
  electron-builder его совместимость нужно проверить заново.
- `builder-util-runtime: 9.7.0`. В этой версии исправлена
  [утечка заголовков авторизации при перенаправлении](https://github.com/electron-userland/electron-builder/security/advisories/GHSA-p2f4-r6v6-j797).
  CommonJS-вход и требования к Node.js совместимы с текущим проектом.

Оставшиеся предупреждения требуют отдельного рассмотрения:

- **Electron 38:** часть advisories исправлена только в новых major.
  До публичного выпуска требуется отдельное обновление Electron с нужными
  исправлениями, проверка приложения и повторный аудит. Текущие ограничения
  навигации, новых окон, webview и разрешений уменьшают доступную поверхность,
  но не устраняют предупреждения движка. До такого обновления не добавляйте
  удалённые страницы, расширения, service workers или произвольный HTML.
- **ExcelJS 4.4.0 → uuid 8.3.2:**
  [advisory касается `v3`/`v5`/`v6` с внешним буфером](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq).
  В установленном ExcelJS найден только `v4()` без буфера в модуле условного
  форматирования; приложение создаёт XLSX, не импортирует пользовательские книги.
  Предлагаемый аудитом откат ExcelJS до `3.4.0` не применяется. При добавлении
  импорта или обновлении библиотеки эту оценку нужно пересмотреть.
- **Tailwind CSS 3:** предупреждения приходят через braces и
  postcss-selector-parser. Они относятся к обработке шаблонов и CSS при сборке;
  приложение не компилирует пользовательский CSS или glob-шаблоны.
  Переход на Tailwind 4 и замена major транзитивных парсеров требуют отдельной проверки.
- **electron-builder и extract-zip:** остаются предупреждения инструментов
  сборки, включая Linux AppImage и извлечение ZIP. Текущие Windows-цели — NSIS
  и portable; это не устраняет риски других целей или недоверенных архивов.

## Артефакты и публикация

CI может создавать неподписанные проверочные артефакты. Windows workflow вызывает
сборку с `--publish never`; загрузка artifacts не публикует релиз и не подтверждает
готовность приложения к публичному распространению. Подпись исполняемых файлов,
публичный выпуск и устранение оставшихся предупреждений проверяются отдельно.
